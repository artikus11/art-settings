# PROJECT_STATUS.md

## 1. Текущие цели этапа

* Реализовать и задокументировать корректную интеграцию библиотеки `art-settings` в плагины экосистемы через Composer (
  VCS).
* Унифицировать передачу конфигурации страниц настроек через единую точку входа `SettingsManager`.
* Разработать расширяемую архитектуру для вывода UI-компонентов (на примере виджета `DownloadBox`) с динамическим
  позиционированием через хуки WooCommerce и передачей динамического контекста рендеринга.
* Предотвратить разрастание `SettingsManager` за счет оптимизации методов получения настроек и структуризации текстовых
  констант.

## 3. Ключевые технические решения

### Единая точка входа настроек и декомпозиция `SettingsManager`

Инициализация страниц опций выполняется исключительно через передачу массива параметров в конструктор `SettingsManager`
с последующим вызовом метода `init()`:

* **Ключ опций в БД:** Задаётся через параметр `option_key` (значение по умолчанию: `art_settings`).
* **Поля формы:** Каждое поле передаётся как объект-наследник базового класса `Art\Settings\Fields\Field`. ID поля
  присваивается менеджером автоматически по ключу массива секции через метод `set_id()`.
* **Нормализация табов:** Метод `SettingsManager::get_normalized_tabs()` поддерживает как ассоциативные массивы, так и
  пользовательские классы с методами `get_label()`, `has_save_button()`, `get_sections()`.
* **Разделение ответственности и борьба с God-Class:** Принято решение не раздувать `SettingsManager` именными геттерами
  под каждое поле. Справочные массивы для UI выносятся в Enums/Константы, а получение значений переводится на
  типизированные базовые геттеры (`get()`, `getString()`, `getInt()`) или доменные DTO по секциям (
  `DownloadBoxSettings`, `BoughtNoteSettings`).

### Динамический маппинг хуков и генерация контекста (DownloadBox)

От жестких пресетов вида `woocommerce_single_product_summary_35` отказались в пользу раздельной схемы:

* В админке выбирается базовый хук вывода (`download_box_hook`) и числовой приоритет (`download_box_priority`).
* Метод инициализации считывает оба параметра и подписывает слушатель через `add_action( $hook, $callback, $priority )`.
* Контекст рендеринга генерируется на лету через `get_download_box_context()` (например, из
  `woocommerce_single_product_summary` и `35` формируется `single-product-summary-prio-35`), что позволяет пробрасывать
  точный BEM-модификатор в шаблон без хардкода карт соответствия.

## 5. Результаты проверки и тестирования

* **Синтаксис Composer:** Конфигурация VCS валидируется Composer; пакет `art/settings: dev-master` резолвится корректно
  при наличии доступа к репозиторию.
* **Нормализация конфигурации:** Метод `SettingsManager::get_normalized_tabs()` корректно обрабатывает смешанные
  структуры (массивы и объекты табов), присваивая ID полям без коллизий.
* **Динамический контекст:** Метод генерации контекста корректно очищает имена хуков от служебных префиксов и формирует
  предсказуемые CSS-классы вида `single-product-summary-prio-35`.
* **Изоляция контекста в шаблонах:** Проброс переменной `$context` через `get_template()` позволяет динамически изменять
  разметку и CSS-модификаторы без дублирования бизнес-логики проверки прав и файлов пользователя.

## 6. Известные ограничения и проблемы

* **Вложенность ассетов `SettingsManager`:** В методе `enqueue_assets` путь к базовой директории вычисляется через
  жесткую привязку `dirname( __DIR__, 2 )`. При изменении структуры каталогов библиотеки вычисление URL/путей к CSS/JS
  потребует ревизии.
* **Зависимость от глобального объекта товара:** Метод `DownloadBox::display_download_box` опирается на глобальный
  `$product`. При использовании хуков за пределами стандартного цикла карточки товара (например,
  `woocommerce_after_single_product`) требуется проверка валидности объекта.

## 7. Опробованные, но отклоненные подходы

* **Жесткие пресеты комбинаций «Хук + Приоритет» (напр., `woocommerce_single_product_summary_35`):** Отклонено.
  Ограничивает настройку под кастомные темы и конструкторы (Elementor, WoodMart). Заменено на два независимых поля (
  Хук + Приоритет).
* **Отдельные DTO/Билдер-классы для табов и секций (`Tab`, `Section`):** Отклонено. Библиотека не содержит отдельных
  классов-строителей структуры; разделение усложняет код без практической пользы. Вся структура приведена к единому
  массиву `$config` с опциональной реализацией методов в кастомных классах табов.
* **Плодение именных get-методов в `SettingsManager` под каждое текстовое поле:** Отклонено. Ведет к превращению сервиса
  в монолитный God-Class. Принят курс на обобщенные геттеры с приведением типов и вынос доменных настроек в DTO.
