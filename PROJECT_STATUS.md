# PROJECT_STATUS.md

## 1. Исходные данные

* **Платформа/Стек:** WordPress / WooCommerce, PHP 8.x, Composer, JavaScript (jQuery, `wp-color-picker`).
* **Экосистема:** Набор кастомных плагинов с общей архитектурной базой и UI-компонентами.
* **Ключевой компонент:** Библиотека `art-settings` (подключается через VCS Composer), отвечающая за генерацию страниц
  настроек в админ-панели на основе декларативной конфигурации.
* **Базовая архитектура полей:** Класс `Field` (абстрактный базовый класс), реализующий методы передачи параметров,
  обработку атрибутов (`get_rendered_attributes()`), санитаризацию (`sanitize()`) и подключение файлов шаблонов из
  `templates/fields/*.php`.

## 2. Текущие цели этапа

* Расширить библиотеку `art-settings` типом поля для выбора цвета (`ColorPicker`) с поддержкой кастомных инлайн-стилей
  layout-обертки.
* Обеспечить корректную фильтрацию `admin_body_class` для всех уровней вложенности страниц настроек (главные и подменю).
* Вынести логику расчета и оформления прогресс-бара акции 1+1=3 из кода плагина промо-акций в конфигурацию настроек
  `SettingsInit`.
* Доработать `SettingsRepository` в библиотеке для удобной выдачи скалярных типов (`get_string`, `get_int`, `get_bool`)
  с поддержкой fallback-значений без создания сервисов-дублей.

  сервисов.

## 4. Ключевые технические решения

### Инлайн-стили для компонентов полей

Добавление кастомных CSS-правил для компонентов полей выполняется через привязку к штатному хэндлу стилей WordPress (
`'wp-color-picker'`).

* **Механизм:** Вызов `wp_add_inline_style( 'wp-color-picker', $custom_css )` регистрирует стили прямо перед выводом
  поля.
* **Результат:** WordPress автоматически группирует правила и выводит единый тег `<style>` в `<head>`, исключая
  дублирование CSS при наличии нескольких полей на странице.

### Фильтрация `admin_body_class` для вложенных меню

Проверка текущего экрана переведена с прямого сравнения `$screen->id === 'toplevel_page_' . $menu_slug` на анализ
родительской базы.

```php
public function admin_body_class( string $body_class ): string {
    $menu_slug = $this->config['menu']['menu_slug'] ?? '';
    $screen    = get_current_screen();

    if ( ! $screen || $screen->parent_base !== $menu_slug ) {
        return $body_class;
    }

    return $body_class . ' ast';
}

```

### Отказ от дублирующих сервисов настроек

Вместо создания индивидуального `SettingsService` в каждом отдельном плагине используется расширенный
`SettingsRepository` библиотеки:

```php
$color_key = ( $progress_percent >= 50 ) ? 'promo_progress_color_mid' : 'promo_progress_color_low';
$color     = $this->settings->get_string( $color_key, '#fbbf24' );

```

## 6. Результаты тестирования и проверки

* **Рендер стилей колорпикера:** Правило `.wp-picker-open + .wp-picker-input-wrap { display: flex; }` успешно
  инъецируется в `<head>` при наличии поля на странице.
* **Переключение цвета порогов:** Метод `render_promo_notice()` корректно меняет цвет прогресс-бара при переходе порога
  в 50%, забирая значения из `promo_progress_color_low` и `promo_progress_color_mid`.
* **Работа на дочерних страницах:** Класс `ast` в `admin_body_class` успешно добавляется как на главных, так и на
  вложенных страницах настроек плагина.

---

## 7. Известные ограничения

* **Отсутствие связи `SettingsRepository` с объектами `Field`:** Репозиторий не содержит ссылки на массив `$config`,
  поэтому значения по умолчанию (`default`) должны явно передаваться в вызовы `get_string('key', 'default_value')`.
* **Зависимость от jQuery:** Скрипт `wp-color-picker` в ядре WordPress жестко завязан на jQuery.

---

## 8. Опробованные, но отклоненные подходы

* **Создание кастомных классов `SettingsService` внутри плагинов:** Отклонено. Приводит к копипасту одинакового кода
  получения полей и их приведения к типам в каждом плагине экосистемы.
* **Передача массива `$config` внутрь `SettingsRepository`:** Отклонено на текущем этапе ради сохранения простоты
  репозитория и отсутствия цикличных зависимостей.
